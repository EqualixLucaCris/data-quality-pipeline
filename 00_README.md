# Data Quality Pipeline

End-to-end ingestion, standardization, validation and analytics pipeline for heterogeneous data files.

## Technologies

- Linux / Bash
- DuckDB
- SQL

## Pipeline

Incoming → Raw → Bronze → Silver → Gold

## Data Versioning Strategy

The repository follows a Medallion-style data architecture while keeping Git focused on source data, pipeline code and final analytical outputs.

- `data/00-incoming/` contains the original source datasets and is version-controlled to make the pipeline reproducible.
- `data/01-raw/` contains ingested source copies generated by the pipeline and is excluded from Git.
- `data/02-bronze/` contains standardized intermediate data and is excluded from Git.
- `data/03-silver/` contains cleaned and validated datasets generated by the pipeline and is excluded from Git.
- `data/04-gold/` contains final analytics-ready datasets and is version-controlled as part of the project deliverables.
- `data/05-rejected/` contains rejected or invalid records and is excluded from Git.
- `.gitkeep` files preserve the Medallion directory structure when generated data is not version-controlled.

Pipeline scripts, SQL transformations, logs, quality reports and documentation are version-controlled.

Local DuckDB databases, temporary working files and other reproducible artifacts are excluded through `.gitignore`.
