# PIPELINE SUMMARY

## Project Overview

The Data Quality Pipeline is an end-to-end local Data Engineering project that ingests heterogeneous source files, standardizes them, validates data quality, separates trusted and rejected records, and produces analytics-ready Gold datasets.

The pipeline is implemented with Bash, DuckDB, SQL, Parquet, Git and GitHub.

## Pipeline Stages

### Incoming

Original source files are preserved without modification.

### Raw

Source files are copied into the Raw layer for traceability and reproducibility.

### Bronze

Technical standardization includes:

- encoding normalization;
- delimiter normalization;
- BOM handling;
- preservation of source business meaning.

### Silver

Silver processing includes:

- profiling;
- schema review;
- NULL and blank-value checks;
- duplicate detection;
- type and date normalization;
- business-rule validation;
- referential-integrity validation;
- clean/rejected separation;
- Parquet export and read-back verification.

### Rejected

Invalid or orphan records are preserved separately where appropriate.

Examples include:

- invalid quantities;
- invalid discounts;
- orphan order references;
- orphan product references.

### Gold

Gold consumes validated Silver data only.

Five analytics-ready datasets were implemented:

1. `gold_completed_order_revenue`
2. `gold_product_performance`
3. `gold_category_performance`
4. `gold_store_performance`
5. `gold_customer_performance`

---

## Business Questions Answered

1. How much net revenue was generated by each completed order?
2. Which products generate the most net revenue, units sold and margin?
3. Which product categories generate the most net revenue and margin?
4. Which stores generate the most net revenue and total margin?
5. Which customers generate the most net revenue and total margin?

---

## Gold Business Rules

- Only validated Silver records are used.
- Only `completed` orders contribute to revenue.
- Only active products are included where applicable.
- Rejected records are excluded from Gold analytics.
- Net revenue is calculated as:

```text
quantity * unit_price * (1 - discount / 100)
```

- Margin is calculated using the effective selling price after discount minus `unit_cost`.
- Monetary metrics are rounded to two decimal places.

## Key Data Quality Issues Handled

The project identified and handled issues including:

- heterogeneous encodings and delimiters;
- duplicate rows;
- duplicate business keys;
- invalid dates;
- NULL values;
- inconsistent boolean values;
- invalid numeric ranges;
- invalid quantities;
- invalid discounts;
- orphan product references;
- orphan order references;
- JSON flattening requirements.

No trusted source values were silently invented.
